# MySQL 5.7.44 兼容性说明

## 适配目标

- 服务端：MySQL Server **5.7.44**，InnoDB，utf8mb4。
- Web 环境：PHP 8.2+、PDO MySQL、Nginx / 宝塔。
- 其他版本：安装程序还接受 MySQL 8.0+。本包并未针对 MariaDB 做安装验收。

## 本次修改点

1. **索引长度**：`reference_values(group_code, value)` 使用 `VARCHAR(40)` 与 `VARCHAR(150)`。即使按 utf8mb4 每字符最多四字节计算，复合唯一索引最大 760 字节，低于旧 InnoDB 配置可能遇到的 767 字节限制。
2. **CHECK 约束**：MySQL 5.7 解析 `CHECK` 却不会实施校验，相关无效建表声明已移除。库存出入库、预留、调拨仍通过 PHP 验证、`SELECT ... FOR UPDATE` 和事务处理，禁止直接修改数据库库存值。
3. **预检查**：安装向导通过 `SELECT VERSION()` 识别 5.7.44，并在建表前检查是否为空库。
4. **选项限制**：后台增加了 150 字符上限，以配合新的列定义。

## 宝塔部署时验证

在宝塔终端或 MySQL 管理窗口执行：

```sql
SELECT VERSION();
SHOW VARIABLES LIKE 'character_set_server';
SHOW VARIABLES LIKE 'innodb_file_per_table';
```

第一个结果应为 5.7.44（或包含类似 -log 后缀）。请使用新建、空的业务数据库，字符集 utf8mb4。

**如果曾尝试使用 v1.0 安装且报错：** MySQL `CREATE TABLE` 不会因为错误自动回滚整套建表。请先确认旧库是否已有真实数据，并备份，然后创建一个全新的空数据库给 v1.1 安装。不要直接删除已有表、不要重复运行安装程序。若已经正常使用 v1.0，请先单独评估数据库迁移，不应直接执行新版 schema.sql。

## 需要在目标服务器完成的验收

1. 成功安装并创建超级管理员。
2. 新建产品，规格、颜色、材质各自正确显示和保存。
3. 新建批次，入库 100 张，出库 30 张；检查库存为 70 张、流水记录正确。
4. 预留 20 张后尝试出库 60 张，应被阻止；解除预留后正常出库。
5. 测试多个员工并发出库，不应超卖或出现负库存。
6. 建立美元订单，手工设置汇率并检查人民币收入与利润，保存报价和费用。
7. 修改字段名称和顺序，重新读取原有记录，确认颜色/材质不串位。
8. 做一次数据库和图片目录的完整备份，并进行恢复演练。

## 注意

数据库兼容修改不等于已经在 MySQL 5.7.44 上通过安装、并发和安全审计。本次本地环境无法启动对应 MySQL 服务，请在实际宝塔测试站完成以上验证后再录入正式库存。MySQL 5.7 已结束常规维护，务必限制数据库公网访问。
